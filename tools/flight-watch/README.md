# מעקב טיסות לזנזיבר — רץ מקומית

סקריפט עצמאי. **בלי npm install ובלי build** — רק `node`. לא נוגע בפרויקט פליי,
לא צריך Postgres, Redis או Railway.

## הפעלה ב-3 שלבים

1. **מפתח**: הירשם ב-serpapi.com, העתק את המפתח ל-`config.json` בשדה `serpApiKey`.
2. **בדיקה**: לחיצה כפולה על `run.cmd`, או:
   ```
   run.cmd --self-test
   ```
   (בודק את לוגיקת השבת מול Hebcal, לא צורך בקשות API)
3. **תזמון**: ראה למטה.

## תזמון אוטומטי (Task Scheduler)

1. פתח **Task Scheduler** → **Create Task** (לא Basic Task).
2. **General**: שם "Zanzibar flights". סמן **Run whether user is logged on or not**? ❌ לא —
   השאר **Run only when user is logged on**, אחרת ההתראה והדפדפן לא יופיעו.
3. **Triggers** → New → **Daily**, חזור **every 3 hours** למשך יום.
4. **Actions** → New → Program: `D:\מירון\סוכנים\tools\flight-watch\run.cmd`
5. **Conditions**: סמן ✅ **Wake the computer to run this task**.
6. **Settings**: סמן ✅ **Run task as soon as possible after a scheduled start is missed**.

שני הסימונים האחרונים חשובים — בלעדיהם מחשב ישן/כבוי פשוט מפספס סריקות.

## מה קורה בכל סריקה

- בונה את כל שילובי התאריכים בחלון (6–8 לילות), **מדלג על יציאה/חזרה בשבת**.
- שלב 1: מתמחר כל שילוב ופוסל טיסות הלוך שנופלות על שבת (בקשה אחת לשילוב).
- שלב 2: רק לשילובים שיכולים להתריע — מאמת גם את טיסות החזור (בקשה שנייה).
- כותב `report.html` ומעדכן `state.json`.
- אם נמצא מחיר מתחת לתקציב: **התראת Windows + פתיחת הדוח בדפדפן**.

מחיר מתחת ל-15% מהסף נחשב "חריג" ומתריע מיד.
אותו מחיר לא יתריע פעמיים — צריך ירידה של 3% לפחות.

## פקודות

| פקודה | מה עושה |
|---|---|
| `run.cmd` | סריקה אחת |
| `run.cmd --self-test` | בודק לוגיקת שבת בלבד (בלי API) |
| `run.cmd --report` | פותח את הדוח האחרון בלי לסרוק |

## עלות

~15 בקשות לסריקה × 8 סריקות ביום ≈ **120 ביום**.
SerpApi: 250 חינם לחודש, $25 ל-1,000, $75 ל-5,000.

להוזלה — ערוך `config.json`:
- `searchesPerRun` מ-12 ל-6 → חצי מהעלות
- או צמצם את `windowStart`/`windowEnd`
- או הרץ כל 6 שעות במקום 3

## המגבלה שצריך להכיר

**מחשב כבוי או ישן = סריקה שלא קרתה.** זה ההבדל האמיתי מול הרצה בענן.
"Wake the computer" ו-"Run task as soon as possible after a missed start"
מכסים את רוב המקרים, אבל לא מחשב שכבוי לגמרי.

לכן: **הפעל במקביל התראות חינמיות** ב-Google Flights ו-Going. הן רצות בענן
ותופסות "mistake fares" שנעלמות תוך שעתיים — בדיוק מה שסריקה כל 3 שעות עלולה
לפספס.

## יתרון לחברה מועדפת (ארקיע)

ב-`config.json`:
```
"preferredAirlines": ["Arkia"],
"preferredBonusUsd": 150,
```
טיסה של חברה מועדפת מתחרה כאילו היא `preferredBonusUsd` דולר זולה יותר — בדירוג
בדוח, בבחירת "הכי זול", ובהתראות. המחיר **האמיתי** תמיד מוצג; הבונוס רק מזיז את
ההשוואה. בדוח היא מסומנת ב-★.

לשנות את גודל היתרון: ערוך את `preferredBonusUsd`. ל-0 = בלי יתרון. להוסיף חברה:
`"preferredAirlines": ["Arkia", "Israir"]`.

⚠️ **מגבלה אמיתית:** ארקיע לזנזיבר היא צ'רטר עונתי, ו-Google Flights (המקור של
הסוכן) לרוב לא מציג צ'רטרים. אז היתרון יעבוד רק אם ארקיע תופיע שם — כדי לתפוס
ארקיע בוודאות, בדוק ישירות ב-arkia.co.il.

## איך נבדקת השבת

זמני שבת מ-Hebcal (חינם, בלי מפתח). החלון האסור הוא **האיחוד** של שני קצוות
המסלול: זנזיבר על קו המשווה ובאותו שעון כמו ישראל, אז השבת שם נכנסת ~74 דקות
מוקדם יותר (18:06 מול 19:20) ויוצאת מוקדם יותר. לוקחים את הכניסה המוקדמת ואת
היציאה המאוחרת — אף פעם לא מקלים.

נפסלת כל טיסה **וכל עצירת ביניים** שחופפת לחלון. כל שדה מתורגם לפי אזור הזמן
שלו (דובאי היא UTC+4, לא +3). שדה שאין לו אזור זמן ידוע נחשב **"לא ניתן לאמת"**
ולא "בטוח" — טעות לכיוון המחמיר.

מוצאי שבת פתוח: טיסה שיוצאת אחרי ההבדלה עוברת.
