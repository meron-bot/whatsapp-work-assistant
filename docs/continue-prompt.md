# פרומט המשך — פיתוח "פליי"

> הדבק את הבלוק הזה בתחילת שיחה חדשה. הוא self-contained.

---

אתה ממשיך פיתוח של **"פליי"** — עוזר עבודה אישי בוואטסאפ של מירון. דבר אליי (מירון) בעברית. אל תכתוב קוד לפני שהבנת את ההקשר: התחל בקריאת הקבצים הרלוונטיים והצג לי תוכנית קצרה לפני כל שינוי. אל תמציא מידע; כשחסר/דו-משמעי — שאל אותי בעברית, אבל מעט ובאצווה.

## המטרה של הסשן
לשנות את ההתנהגות של פליי שיהיה **חכם ולא מתשאל**, ולהוסיף יכולות. **פרט למסלול הדחוף (תמלול קולי) בסוף — אל תשבור התנהגות קיימת.**

## הפרויקט
- **Repo:** `meron-bot/whatsapp-work-assistant` · **branch:** `claude/cool-bardeen-X8vTx`
- **Stack:** NestJS + TypeScript · Prisma + PostgreSQL · תור inline (בלי Redis). פרוס ב-**Railway** (auto-deploy על push).
- **URL:** https://work-assistant-production-e5b0.up.railway.app · **אבחון:** `/status` (JSON) ו-`/admin` (דאשבורד).
- **AI:** Anthropic = planner (Haiku ברירת מחדל, מסלים ל-Sonnet במורכב; מסמכים רשמיים = Sonnet). OpenAI = תמלול קול + תמונות בלבד.
- **מודולים קיימים:** `src/google` (calendar, gmail, docs, drive, tasks) · `src/media` · `src/planner` · `src/processing` · `src/scheduler/daily-planning` · `src/memory`.
- **מגבלה קריטית:** Node לא מותקן על המחשב של מירון — **אי אפשר build/test מקומית**. דוחפים ל-GitHub, Railway בונה. מאמתים דרך `/status` ו-`/admin` (אפשר `curl`). כל הסודות מוגדרים ב-Railway.

## מה כבר נבנה — בנֵה על זה, אל תשכפל
**שכבת למידה (`src/memory`) כבר ממומשת ועובדת:**
- מודל Prisma `LearnedFact` + enum `MemoryType` (preference / contact / project_fact / pattern / correction / glossary), מיגרציה `0003_learned_facts`.
- `LearnedFactService`: `retrieveForPrompt` (התאמת מילות-מפתח, בלי embeddings; preference/glossary תמיד מוזרקים; תקרה 12), `applyWrites` (dedup + חיזוק confidence), `listActive`, `forget`.
- ה-planner כבר פולט `memoryWrites` (תוצר-לוואי, בלי קריאת AI נוספת), והעובדות מוזרקות לפרומט כ-"Known facts about the owner".
- פקודות דטרמיניסטיות בלי AI ב-`message-processor`: "מה אתה זוכר" ו-"תשכח ש...".

פליי כבר זוכר העדפות/אנשי קשר — השתמש בזה (במיוחד `type=contact` לאנשי קשר). מפרט עיצוב מלא: `docs/ideal-agent-spec.md`.

## עקרון-העל ההתנהגותי החדש: פליי פותר לבד לפני שהוא שואל
היום ה-planner בנוי על "חסר מידע → שאל". זה הבאג. החלף ב**סולם פתרון** — פליי שואל את מירון רק כמוצא אחרון:
1. **הבן** מההקשר (ההודעה, השיחה, LearnedFacts, פרויקטים).
2. **חפש** (יומן, Gmail, הודעות קודמות, אנשי קשר).
3. **האצל** לסוכן-משנה (מחקר/מייל/יומן/מסמכים) שיביא את ההקשר החסר.
4. **הנח** הנחה סבירה ותגיד אותה ("קבעתי ל-9:00, 60 דק', תקן אם צריך").
5. רק עכשיו **שאל** את מירון — באצווה אחת, כל מה שחסר בהודעה אחת. בלי טפטוף שאלות.

מותר לשאול רק כששלושת התנאים יחד: המידע הכרחי · אי אפשר להסיק/להניח · טעות יקרה/בלתי הפיכה. אחרת — פעֵל ודווח בשורה.

## מדיניות אישורים — תירית
- **אוטומטי + דיווח:** פעולות פנימיות/הפיכות (משימה, תזכורת, החזקת יומן), **וזימון פגישה לאנשים מוכרים/פנימיים.**
- **טיוטה + אישור בלחיצה:** מייל/זימון ללקוחות/חיצוני/רגיש, וכל מה שנוגע לכסף/חוזים/מחיקות.

## יומן וזימונים
- צור אירוע ביומן עם המשתתפים → גוגל שולח זימון. הוסף **Google Meet כברירת מחדל**, משך **60 דק'** אלא אם נאמר אחרת.
- כתובות מייל של משתתפים: חפש לבד ב-Gmail/אנשי קשר; אם לא מצאת — שאל פעם אחת ושמור ל-`LearnedFact` (type=contact) להבא.

## סוכני-משנה שפליי מנהל (4)
מחקר ברשת · קריאה/חיפוש ב-Gmail · ניהול יומן (זמינות/חלונות/קביעה) · ניסוח מסמכים/דוחות.
פליי קורא להם להשלמת הקשר **לפני** שהוא שואל את מירון, ומדווח בקצרה מה גילה.

## אחסון מסמכים: Drive + מחשב
שמור כל מסמך שנוצר ל-Google Drive במבנה:
```
פליי / עבודה / <פרויקט|לקוח|דוחות|פגישות וסיכומים|מסמכים רשמיים>
פליי / פרטי
```
תת-התיקיות תחת "עבודה" נפתחות אוטומטית לפי הצורך; פליי מנתב לפי ההקשר. עותק במחשב = הסתמכות על **Google Drive Desktop** (הקובץ בתיקיית Drive מופיע ב-PC). במקביל שלח את הקובץ גם בוואטסאפ.

## תדריך יומי 08:00
שנה את `DAILY_PLAN_TIME` ל-08:00 (`src/scheduler/daily-planning.service` + env). העשר את התוכן: כל בוקר עבור על יומן + משימות פתוחות + לולאות פתוחות, ושלח: **לו"ז מסודר של היום** (פגישות + חלונות פנויים), **פעולות להמשך** (דד-ליינים, מעקבים), ו**הצעות חכמות** לניצול זמן.

## רשימת השינויים לביצוע
1. שכתב את פרומט ה-planner (`src/planner/planner.prompt.ts`) + הסכמה (`planner.schema.ts`) כך שיקודדו את סולם הפתרון + המדיניות התירית. הוסף שדות שמאפשרים ל-planner לבקש קריאה לכלי/סוכן-משנה לפני clarification.
2. הוסף שלב "פתרון" ב-`src/processing/message-processor.service.ts`: לפני יצירת clarification, נסה כלים (חיפוש יומן/Gmail/רשת). רק אם נכשלו — שאל, ובאצווה.
3. העלה את סף ההבהרה ב-`src/actions/action-policy.ts` (confidence/risk) כך שיֵשאל הרבה פחות.
4. זימוני יומן מלאים: `src/google/google-calendar.service` — יצירת אירוע עם attendees + conferenceData (Meet) + שליחת זימון. נתב לפי המדיניות התירית.
5. איתור + זכירת אנשי קשר: חיפוש ב-Gmail, ושמירה ל-`LearnedFact` (type=contact).
6. שכבת אורקסטרציה ל-4 סוכני-המשנה ככלים שה-planner יכול להפעיל (בנה על `src/memory` ו-`src/google` הקיימים).
7. מבנה תיקיות ב-Drive + ניתוב מסמכים אוטומטי (`src/google/google-drive.service` + `google-docs.service`).
8. משלוח קובץ בוואטסאפ (`src/whatsapp`) + הסתמכות על Drive Desktop לעותק מקומי.
9. תדריך יומי ב-08:00 מועשר (כמתואר למעלה).

## מסלול דחוף נפרד: הקלטות קוליות לא עובדות
**בעיה:** תמלול קולי נכשל עם "Connection error". **האבחנה:** OpenAI SDK v4.67 נכשל בהעלאת multipart על Node 20 (api.openai.com עצמו נגיש — `/connectivity` מחזיר 401 מהיר). כבר נדחף תיקון (**commit `310742d`**) שמחליף את `client.audio.transcriptions.create` ב-fetch ילידי + FormData + Blob ב-`src/ai/openai.provider.ts` — אבל הפריסה ב-Railway נתקעה ולא עלתה (חשד: שגיאת קומפילציה מהתנגשות טיפוסים בין Blob של Node ל-undici, או build שנכשל). **מה לעשות:**
- בדוק ב-Railway אם ה-build של `310742d` נכשל וקרא את שגיאת ה-build.
- אם זו התנגשות טיפוסים: עשה cast ל-`(new Blob([audio], {type}) as any)` ב-`form.append`, או השתמש ב-undici FormData/Blob במפורש. ודא ש-`tsc` עובר.
- אחרי פריסה: בדוק `/status` (`status:ok`, `schemaReady:true`) ושלח הקלטה; ודא transcript לא ריק ב-`/admin/media` (יש שם עמודת `processingError` לאבחון), ושמתקבלת תשובה בעברית.
